# النسخ الاحتياطي والاستعادة

## ما يُنسخ

`infra/backup/backup.sh` يأخذ نسخة كاملة من قاعدة البيانات (`pg_dump`) وصور الأصناف وصور إشعارات التحويل البنكي (مجلد `/private` الذي لا يخدمه الخادم الأمامي)، ويشفّرها بـAES-256 بالمفتاح `infra/prod/backup.key`، ويحفظها في `RAFF_BACKUP_DIR` (افتراضياً `/var/backups/raff`) مع ملف `.sha256`. يبقى آخر `RAFF_BACKUP_KEEP` نسخة (افتراضياً 14).

يعمل ليلياً الساعة 02:30 (من `install.sh`). نتيجة كل نسخة تظهر في **الإعدادات › آخر نسخة ناجحة**، والفشل يظهر هناك ويُسجَّل في سجل التدقيق.

## نسخة خارج الخادم

ضع في `infra/prod/.env` أحد الخيارين:

```
RAFF_BACKUP_REMOTE=backup@203.0.113.10:/backups/raff     # rsync عبر SSH (مفتاح SSH بلا كلمة مرور لمستخدم root)
RAFF_BACKUP_REMOTE=rclone:gdrive:raff                    # rclone مُعدّ مسبقاً (rclone config)
```

## نسخة يدوية الآن

```bash
sudo infra/backup/backup.sh
```

## اختبار الاستعادة (أسبوعياً تلقائياً)

```bash
sudo infra/restore.sh --verify-latest
```

يفك آخر نسخة ويستعيدها في قاعدة مؤقتة ويتحقق منها ثم يحذفها، ويسجّل التاريخ في **الإعدادات › اختبار الاستعادة**. لا يمس البيانات العاملة.

## استعادة على هذا الخادم

```bash
sudo infra/restore.sh /var/backups/raff/raff-20261022-023000.tar.enc --key infra/prod/backup.key
```

> تحذير: تستبدل البيانات الحالية بالكامل بمحتوى النسخة. أوقف البيع قبلها.

## استعادة على خادم بديل نظيف (بأمر واحد)

على خادم جديد عليه Docker والمستودع (الخطوتان 1 و2 من `install.md`):

```bash
sudo infra/restore.sh /path/raff-20261022-023000.tar.enc --key /path/backup.key --domain pharmacy.example.com
```

يأخذ معرّف المؤسسة من النسخة، ويولّد أسراراً جديدة، ويبني ويشغّل ويستعيد البيانات والصور. بعد انتهائه وجّه النطاق إلى الخادم الجديد. أعد جدولة النسخ بتشغيل `install.sh` بنفس الخيارات (لن يغيّر البيانات).

## أعطال شائعة

| الرسالة | السبب | الحل |
|---|---|---|
| `Checksum mismatch` | الملف تالف أثناء النقل | انسخه مجدداً أو استعمل نسخة أقدم |
| `Could not decrypt (wrong key?)` | مفتاح خاطئ | استعمل `backup.key` الأصلي |
| `This server serves organization …` | نسخة مؤسسة أخرى | استعملها على خادم نظيف |


## صور إشعارات التحويل البنكي

تُحفظ في مجلد خاص (`RAFF_PRIVATE_ROOT`، في الحاوية `/private`) خارج `/media` فلا تُخدم للعموم، ويقرؤها موظفو الطلبات فقط عبر واجهة بصلاحية. تُحذف تلقائياً بعد `RAFF_RECEIPT_RETENTION_DAYS` (90 افتراضياً) من إكمال الطلب أو إلغائه، بأمر `manage.py purge_receipts` الذي يشغّله `backup.sh` في كل نسخة. النسخ الاحتياطية القديمة (قبل هذه الميزة) تُستعاد بلا هذا المجلد.
