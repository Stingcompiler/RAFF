# 0002 — الواجهة على إعدادات المتصفح الافتراضية (بلا Tailwind preflight)

- الحالة: معتمد
- التاريخ: 2026-10-22
- أمر العمل: WO-01

## السياق

ملفات التصميم المعتمدة تُرسم بلا أي إعادة ضبط CSS: كل `div` و`span` بـ`box-sizing: content-box` (حقل بارتفاع 44px وحد 1px يظهر 46px)، والأزرار بقياسات المتصفح الافتراضية. Tailwind يضيف preflight الذي يحوّل كل شيء إلى `border-box` ويصفّر الهوامش وخطوط الأزرار، فتنحرف كل شاشة عن مرجعها البصري بعدة بكسلات تتراكم.

## القرار

1. `globals.css` يستورد `tailwindcss/theme.css` و`tailwindcss/utilities.css` فقط، بلا preflight. القواعد الأساسية الوحيدة هي ما تضعه ملفات التصميم نفسها: `body { margin: 0 }`، و`font-family: inherit` للأزرار والحقول، ولون الروابط.
2. تُنقل قيم التصميم كما هي: `h-[44px]` مع `border` يعطي 46px كما في التصميم.
3. لا يُستخدم `border-solid` مع حدود جانب واحد. بلا preflight يصبح عرض الجوانب الأخرى `medium` (3px). Tailwind v4 يضبط نمط الجانب مع `border-b`/`border-t`/`border-e`. الحد المتقطع لجانب واحد يُكتب كخاصية واحدة: `[border-top:1px_dashed_…]`.
4. حين يُستعمل `<button>` مكان `span` في التصميم، يرث الخط بـ`type-inherit` لأن خط الزر لا يُورث افتراضياً. `leading-normal` في Tailwind تعني 1.5؛ لقيمة CSS `normal` يُكتب `leading-[normal]`.

## العواقب

- مطابقة بصرية دقيقة: صفحة `/dev/components` تختلف 0.35% عن مرجعها بالارتفاع نفسه، والقشرة 0.00%.
- على المطوّر تذكّر القواعد 2–4. الأخطاء فيها تظهر فوراً في اختبار `visual`.
